# 开发工作流最佳实践指南 (Superpower Engineering)

本指南遵循 Superpower 工程化方法论，指导研发人员与 AI 编程智能体高质量落地代码。

---

## 一、TDD (测试驱动开发) 黄金法则

1. **先写失败的测试**：在未编写功能实现代码前，必须先写针对接口契约的单元测试，并运行确认其报红（Red）。
2. **写最小可用实现**：编写只够让测试通过的代码（Green），避免过度设计与预判未发生的需求。
3. **安全重构**：测试通过后，清理冗余代码、重构类名与提取公共函数，确保测试仍然全部通过（Refactor）。

---

## 二、微任务拆解准则

- **单一职责**：一个微任务只做一件事（例如：“仅实现 ANSI 颜色代码正则剥离器”）。
- **可独立验证**：每个任务必须附带一条可直接在命令行运行的验证命令（如 `npm test -- filter.test.ts` 或 `go test -v ./...`）。
- **原子提交 (Atomic Commits)**：每一个微任务完成后立即执行 Git commit，Commit Message 必须包含清晰动词（`feat:`, `fix:`, `refactor:`, `test:`）。

---

## 三、代码安全与内网合规底线

- **严禁硬编码秘钥**：任何 AppID、Secret、Token 一律从环境变量或安全配置文件读取，严禁提交到 Git。
- **脱敏日志**：生产/远程上传日志必须进行敏感数据屏蔽（邮箱、手机号、内网私有域名、项目绝对路径等）。
