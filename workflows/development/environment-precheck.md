# 环境预检工作流 (Environment Precheck)

在开始任何技术实现、Bug 修复或重大重构前，必须先执行环境预检，全方位排查当前环境状态与潜在冲突，杜绝“带病开工”。

---

## 五维预检清单

### 1. 代码与 Git 环境
- [ ] **当前工作区状态**：执行 `git status`，确认工作树是否干净，避免混入无关变更。
- [ ] **分支与远端状态**：确认当前分支是否正确，拉取远端更新，检查是否有未解决的冲突。

### 2. 需求与设计基线
- [ ] **PRD 定位**：关联的 PRD 是否已通过评审并冻结。
- [ ] **TRD 契约**：接口签名契约、数据模型是否已明确。
- [ ] **历史方案比对**：是否与既有模块的架构设计存在冲突。

### 3. 构建与编译器状态
- [ ] **基线编译**：执行工程编译检查，确保起始代码可顺利构建通过。
- [ ] **基线测试**：执行基准测试命令，确认当前测试状态是否为 0 失败（若有既有失败，需先记录或归因）。

### 4. 依赖与基础设施
- [ ] **本地依赖完备性**：Node / Go / Java / Python 版本是否符合工程要求。
- [ ] **中间件可用性**：本地 SQLite / Redis / Docker / Mock 服务是否就绪。

### 5. 安全与网络合规
- [ ] **内网防火墙状态**：外网 API 请求是否受阻，必要时切换为离线或 Mock 模式。

---

## 阶段流转重新预检触发点
当任务发生如下阶段切换时，必须重新执行预检：
1. 从 **方案讨论/设计阶段** 进入 **编码实施阶段**。
2. 从 **本地单测验证** 进入 **联调与集成测试**。
3. 发现新增了此前未预料的环境域（如新增依赖外部数据库或云函数）。
