# 风险门控规范 (Risk Gate)

在执行任何可能产生不可逆后果、环境破坏或数据安全风险的操作前，必须通过风险门检查。

---

## 风险等级划分

### 🔴 高风险操作（必须向用户明确确认后方可执行）

| 操作类型 | 典型场景 | 必须确认的内容 |
| :--- | :--- | :--- |
| **破坏性 Git 操作** | `git push -f`、`git reset --hard`、删除远端分支、覆盖他人提交 | 影响范围、有无备份、回滚路径 |
| **生产/外部数据写入** | 生产数据库迁移、删表/删库、真实业务接口写入 | 操作环境、数据备份情况、降级回滚方案 |
| **敏感凭据与外泄风险** | 上传/打印密钥、将内网机密代码外传第三方公网服务 | 脱敏审查、权限合规性 |
| **并发写入冲突** | 多个 Agent 或进程并行修改同一关键文件 | 写入范围隔离策略、锁机制 |

### 🟡 中风险操作（建议确认，可降级处理）

| 操作类型 | 典型场景 | 推荐降级策略 |
| :--- | :--- | :--- |
| **依赖与基础库变更** | 升级核心依赖包版本、修改构建配置 | 先在本地隔离分支/Worktree 测试后再合并 |
| **公共 API 契约变更** | 修改请求/响应字段、变更状态机状态 | 先确认向后兼容性 (Backward Compatibility) |
| **数据库 Schema 变更** | 新增/修改数据表字段、新增索引 | 编写并验证回滚 SQL/脚本 |

### 🟢 低风险操作（可自动执行）

- 只读操作：查看文件、检索代码、查询 Git 状态
- 本地只读构建与单测执行：编译、运行测试用例
- 本地编写方案、拆解任务清单与文档整理

---

## 降级与兜底策略

当高风险操作被用户拒绝或无法确认时，采用如下降级路线：
1. **真实服务调用** ➡️ 降级为 **Mock 数据/桩代码** 验证核心逻辑。
2. **直接修改主分支** ➡️ 降级为 **新建分支 / Git Worktree** 隔离开发。
3. **高风险并发改动** ➡️ 降级为 **单线程顺序执行**。
