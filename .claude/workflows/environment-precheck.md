# 环境预检工作流（Claude Code 适配版）

在开始任何任务前，先执行环境预检，识别任务触达的所有环境域和风险。

## 预检清单

### 1. 代码/Git 环境

| 检查项 | 命令/方法 | 目的 |
|--------|----------|------|
| 仓库根目录 | 确认当前工作目录 | 确保在正确项目中 |
| Git 状态 | `git status` | 了解工作区是否干净 |
| 当前分支 | `git branch --show-current` | 确认在正确分支上工作 |
| 未提交变更 | `git diff --stat` | 了解已有变更范围 |
| 远端同步状态 | `git fetch --dry-run` | 了解远端是否有新提交 |

### 2. 文档/需求环境

| 检查项 | 方法 | 目的 |
|--------|------|------|
| PRD 定位 | 读 `docs/PRD/README.md` | 找到相关子文档 |
| TAD 定位 | 读 `docs/TAD/README.md` | 找到相关技术架构 |
| TEST 定位 | 读 `docs/TEST/README.md` | 找到相关测试用例 |
| 迭代计划 | 检查 `docs/superpowers/plans/` | 是否已有相关计划 |
| 设计文档 | 检查 `docs/superpowers/specs/` | 是否已有相关设计 |
| API 契约 | 读 `docs/api/openapi.yaml` | 接口定义 |
| 数据库 | 读 `docs/database/schema.md` | 表结构 |

### 3. UI/前端环境

> 本项目为后端服务，通常不触达 UI/前端环境域。若涉及 API 响应结构对前端的影响，确认接口契约与 `openapi.yaml` 一致即可。

### 4. 生产/运维环境

| 检查项 | 方法 | 目的 |
|--------|------|------|
| 目标环境 | 确认是 local/test/production | 界定安全边界 |
| 回滚路径 | 确认是否有回滚方案（镜像 tag、SQL 回滚） | 生产写入前必须确认 |
| 部署方式 | 检查 `.gitlab-ci.yml`、`docker-compose.yml` | 了解发布流程 |
| 配置 profile | 检查 `application-{local,test}.yml` | 确认配置差异 |

### 5. 测试环境

| 检查项 | 命令/方法 | 目的 |
|--------|----------|------|
| 现有测试 | `mvn test` | 了解当前测试状态 |
| 测试覆盖 | 检查 `src/test/java/` 目录 | 了解已有测试范围 |
| CI 状态 | 检查 `.gitlab-ci.yml` | 了解 CI 流程（当前 CI 只做镜像构建推送） |
| 测试依赖 | H2 / Testcontainers MySQL | 确认集成测试基础设施 |

## 预检输出格式

完成预检后，输出简短摘要：

```markdown
## 环境预检结果

**触达环境**：代码/Git、文档/需求、测试
**风险等级**：🟢 低风险 / 🟡 中风险 / 🔴 高风险
**推荐路由**：/tdd-flow / /bug-fix / 快速通道
**关键发现**：
- 当前分支：feature/xxx
- 工作区状态：干净 / 有未提交变更
- 相关文档：PRD/xx、TAD/xx、TEST/xx
```

## 与 Superpowers 编排器的集成

环境预检是 Superpowers 编排器的第一步：

```
用户请求
    │
    ▼
① 环境预检（本文档）
    │
    ▼
② 风险门（risk-gate.md）
    │
    ▼
③ 路由选择（superpowers-orchestrator.md）
    │
    ▼
④ 子技能执行
    │
    ▼
⑤ 验证与完成
```

## 阶段转换时重新预检

以下情况需要重新执行环境预检：

- 任务从**讨论**进入**实现**
- 任务从**调试**进入**修复**
- 任务从**本地验证**进入**生产验证**
- 任务从**实现**进入**交付**
- 发现新的环境域被触达（如原本只改代码，后来发现需要改文档/SQL）
