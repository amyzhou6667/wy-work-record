# Agent: 完成前验证

command: /verify

## 职责

在声称任务完成、修复、通过或可发布之前，必须执行验证并用最新证据支撑结论。

## 触发条件

- 即将输出"完成"、"修复"、"通过"、"可发布"等结论
- 准备提交代码（`git commit`）
- 准备推送代码（`git push`）
- Review 通过后准备交付

## 验证清单

### 代码变更验证

| 检查项 | 验证方法 | 通过标准 |
|--------|---------|---------|
| 测试全部通过 | `mvn test` | 0 失败 |
| 代码无编译错误 | `mvn -q -DskipTests compile` | BUILD SUCCESS |
| 变更符合验收标准 | 对照迭代计划逐项检查 | 每项 AC 有对应实现 |
| 无遗留调试代码 | 检查 `System.out`、`e.printStackTrace()`、`// TODO` 调试注释 | 无调试输出残留 |
| 无硬编码测试数据 | 检查实现代码 | 无测试专用数据/凭据 |

### 文档同步验证

| 检查项 | 验证方法 | 通过标准 |
|--------|---------|---------|
| 新类/新模块 → TAD 已更新 | 对照变更文件列表 | TAD 有对应描述 |
| 接口/模型/SQL 变更 → TAD 已更新 | 对照 API/SQL 变更 | TAD 描述与代码一致 |
| 行为变更 → TEST 已更新 | 对照功能变更 | TEST 有对应 TC |
| 迭代计划 → 已创建/更新 | 检查 `docs/superpowers/plans/` | 计划文档存在且内容完整 |

### Git 验证

| 检查项 | 验证方法 | 通过标准 |
|--------|---------|---------|
| 代码和文档在同一 commit | `git log --oneline -1` + `git show --stat` | 同一 commit 包含代码+文档 |
| Commit message 符合规范 | 检查格式 | `<type>(<scope>): <subject>` |
| 测试通过标记已写入 | `cat .git/.test_passed` | 标记与当前 HEAD 一致 |

## 验证输出格式

```markdown
## 完成验证报告

**任务**：<任务描述>
**验证时间**：<时间>

### 代码验证
- [x] mvn test: 0 失败
- [x] mvn compile: BUILD SUCCESS
- [x] 验收标准: 全部满足
- [x] 调试代码: 已清理
- [x] 硬编码数据: 无

### 文档验证
- [x] TAD 同步: 已更新
- [x] TEST 同步: 已更新
- [x] 迭代计划: 已创建/更新

### Git 验证
- [x] 代码+文档同一 commit
- [x] Commit message 规范
- [x] 测试通过标记已写入

### 未验证风险
<列出尚未验证的剩余风险，或"无">
```

## 核心原则

1. **不声称完成，除非已执行验证**：验证是结论的前提，不是可选步骤
2. **用证据说话**：每个"通过"背后都有具体的命令输出或检查结果
3. **诚实报告未验证项**：如果某些验证无法执行（如生产环境验证），明确说明
4. **验证证据必须是最新的**：不能使用之前的验证结果来支撑当前的结论

## 与其他流程的集成

- `/tdd-flow`：阶段④ Review 通过后，执行完成前验证
- `/bug-fix`：步骤⑤ Review 通过后，执行完成前验证
- `/superpowers`：路由到任何子技能完成后，执行完成前验证
- 手动实现：准备 `git commit` 前，执行完成前验证
