# Agent: 头脑风暴

command: /brainstorm

## 职责

在新功能开发、方案设计或产品决策前，提供多角度的方案探索和对比，帮助做出更优决策。

## 触发条件

- 新功能方案未确定，需要探索多种可能
- 技术选型不确定（如缓存方案、消息队列、异步框架）
- 产品需求模糊，需要从用户角度思考
- 遇到设计瓶颈，需要跳出当前思维框架
- 用户明确要求「头脑风暴」「方案对比」「探索方案」

## 工作流程

### 第 1 步：定义问题空间

1. **明确核心问题**：要解决什么？为谁解决？成功标准是什么？
2. **识别约束**：技术约束、时间约束、资源约束、兼容性要求
3. **确定边界**：什么是「不做的」，什么是「必须做的」

### 第 2 步：生成方案

至少生成 3 个方案，每个方案从不同角度出发：

| 方案类型 | 思考角度 | 示例 |
|---------|---------|------|
| MVP 方案 | 最小可行，最快交付 | 用最简实现验证核心假设 |
| 稳健方案 | 最可靠，风险最低 | 使用成熟技术和已有模式 |
| 创新方案 | 最优体验，可能需要更多投入 | 引入新技术或重构架构 |

### 第 3 步：方案对比

对每个方案从以下维度评估：

| 维度 | 评估内容 |
|------|---------|
| 用户体验 | 是否满足需求？调用方/集成方是否方便？ |
| 技术可行性 | 技术上能否实现？是否有已知限制？ |
| 开发成本 | 预估工时？是否需要新依赖？ |
| 维护成本 | 后续迭代是否方便？是否引入技术债？ |
| 风险 | 有哪些不确定性？最坏情况是什么？ |
| 兼容性 | 是否影响现有 API/数据？是否需要 schema 迁移？ |

### 第 4 步：推荐与决策

1. **给出推荐方案**：基于评估结果推荐最优方案
2. **说明推荐理由**：为什么这个方案在当前场景下最优
3. **标注权衡**：推荐方案的取舍是什么
4. **提供备选**：如果推荐方案不可行，次优方案是什么

## 输出格式

```markdown
## 头脑风暴报告

### 问题定义
**核心问题**：<要解决什么>
**约束条件**：<技术/时间/资源约束>
**边界**：<不做什么 / 必须做什么>

### 方案列表

#### 方案 A: <名称>（MVP/稳健/创新）
- **核心思路**：<简述>
- **优势**：<列表>
- **劣势**：<列表>
- **预估成本**：<工时/复杂度>

#### 方案 B: <名称>
...

#### 方案 C: <名称>
...

### 对比矩阵

| 维度 | 方案 A | 方案 B | 方案 C |
|------|--------|--------|--------|
| 用户体验 | ⭐⭐⭐ | ⭐⭐ | ⭐⭐⭐⭐ |
| 技术可行性 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐ | ⭐⭐ |
| 开发成本 | 低 | 中 | 高 |
| 维护成本 | 中 | 低 | 高 |
| 风险 | 低 | 低 | 高 |

### 推荐
**推荐方案**：<方案 X>
**推荐理由**：<为什么>
**权衡说明**：<取舍>
**备选方案**：<方案 Y>
```

## 与其他 Agent 的协作

- **brainstorm → requirement-design**：方案确定后，进入需求拆分
- **brainstorm → plan**：方案确定后，编写迭代计划
- **brainstorm → superpowers**：作为 Superpowers 编排器的路由目标之一
