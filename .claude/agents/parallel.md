# Agent: 并行开发

command: /parallel

## 职责

当多个不相关任务可以并行执行时，负责调度多个子 Agent 并行工作，提高效率。

## 触发条件

- 多个不相关的 Bug 需要同时修复
- 多个独立模块的功能需要同时开发
- 用户明确要求并行执行
- 任务规模大，可以拆分为独立子任务并行

## 并行调度原则

### 可并行的条件

所有条件必须同时满足：

1. **写入范围不重叠**：每个子任务修改不同的文件
2. **无共享可变状态**：子任务之间不共享数据库、向量索引、全局状态或运行时资源
3. **可独立验证**：每个子任务有自己的验证命令和验收标准
4. **无依赖关系**：子任务之间没有先后依赖

### 不可并行的情况

- 子任务修改同一文件
- 子任务共享 schema 迁移或测试数据
- 子任务之间有数据依赖
- 子任务需要同一资源（如数据库、文件锁、同一 mapper）

## 工作流程

### 第 1 步：任务分析

1. **列出所有子任务**
2. **分析每个子任务的写入范围**（修改哪些文件）
3. **识别依赖关系**（子任务之间是否有依赖）
4. **确定并行分组**（哪些可以并行，哪些必须串行）

```markdown
## 任务分析

| 子任务 | 写入范围 | 依赖 | 可并行组 |
|--------|---------|------|---------|
| A: 修复会话 Bug | src/main/java/.../conversation/ | 无 | 组 1 |
| B: 修复记忆 Bug | src/main/java/.../memory/ | 无 | 组 1 |
| C: 更新集成网关 | src/main/java/.../integration/ | 无 | 组 1 |
| D: 适配新网关接口 | src/main/java/.../conversation/, .../memory/ | C | 组 2 |
```

### 第 2 步：并行执行

对每个并行组，同时启动多个子 Agent：

```
组 1（并行）：
├── Agent A: 修复会话 Bug
├── Agent B: 修复记忆 Bug
└── Agent C: 更新集成网关

组 2（串行，依赖组 1 完成）：
└── Agent D: 适配新网关接口
```

### 第 3 步：结果收集

1. **等待所有并行任务完成**
2. **收集每个子任务的输出**
3. **检查是否有冲突**（尽管写入范围不重叠，仍需确认）
4. **汇总结果**

### 第 4 步：集成验证

1. **合并所有子任务的变更**
2. **执行全量测试**：`mvn test`
3. **检查集成点**：子任务之间的接口是否兼容
4. **如有失败**：定位是哪个子任务引入的问题，单独修复

### 第 5 步：输出报告

```markdown
## 并行开发报告

### 并行组 1
| 子任务 | Agent | 状态 | 结果 |
|--------|-------|------|------|
| A: 修复会话 Bug | code-dev | ✅ 完成 | 修改 2 文件，测试通过 |
| B: 修复记忆 Bug | code-dev | ✅ 完成 | 修改 3 文件，测试通过 |
| C: 更新集成网关 | code-dev | ✅ 完成 | 修改 1 文件，测试通过 |

### 集成验证
- mvn test: 48 passed, 0 failed
- 集成点检查: 通过

### 后续
- 需要进入 Review 阶段
- 需要文档同步
```

## 并行 Agent 调度方式

在 Claude Code 中，使用 Agent 工具并行启动子 Agent：

```
# 并行启动多个 Agent
Agent("修复会话 Bug", ...)  # 同时启动
Agent("修复记忆 Bug", ...)  # 同时启动
Agent("更新集成网关", ...)  # 同时启动
```

## 风险控制

| 风险 | 预防措施 |
|------|---------|
| 写入冲突 | 并行前严格分析写入范围 |
| 测试干扰 | 每个子任务使用独立的测试类 |
| 集成失败 | 并行组之间留有集成验证步骤 |
| 推送冲突 | 子任务只本地提交，推送回到风险门 |

## 与其他 Agent 的协作

- **parallel → code-dev**：每个子任务调用 code-dev Agent
- **parallel → tdd**：每个子任务完成后调用 tdd Agent 验证
- **parallel → review**：集成验证后调用 review Agent
- **parallel → superpowers**：作为 Superpowers 编排器的路由目标之一
